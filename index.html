🌡 What the Model Listens To

Random Forest feature importance. One feature towers over the 55 sensors: Temperature_F (24.2%) — see the dataset note below for why, it is a quirk of how the data was recorded, and the model leans on it honestly.

🗂 Dataset & Features

PIRVision office dataset — 7,651 observations from 8 Aug to 8 Oct 2024, each with a timestamp, a temperature reading, and 55 PIR (passive infrared) sensor readings from an office room.

  • Engineered features: Date + Time are converted into Hour, Minute, Second and DayOfWeek, giving 60 model features (55 PIR + temperature + 4 time features).
  • Clean by count: 0 missing values and 0 duplicate rows — the pipelines still include a median imputer, so a missing reading at prediction time can never crash the model.
  • Honest quirk 1: every Other Activity row records Temperature_F = 0, while the other classes average about 86–87 °F. That recording artifact is exactly why temperature is the #1 feature.
  • Honest quirk 2: PIR readings sit near 10,000 at rest, but Other Activity rows average ≈ 68,659 per sensor and single readings spike as high as 111,602,625 — motion floods the sensors.
  • Labels are 0, 1 and 3 — there is no class 2 in this dataset. Class imbalance (81.6% Vacancy) is handled with class_weight='balanced' and a stratified split.

⚙️ Pipeline — Notebook to Live Model

  1. Load & explore — 7,651 × 59 table; class distribution, temperature and PIR behaviour checked.
  2. Feature engineering — Date/Time → Hour, Minute, Second, DayOfWeek; 60 numeric features.
  3. Split — 80/20 stratified, random_state 42 → 6,120 train / 1,531 test.
  4. Four pipelines — median imputer first; StandardScaler added for KNN and SVM only (tree models do not need it); balanced class weights.
  5. Compare & select — Random Forest best on accuracy and macro F1.
  6. Export & serve — the whole pipeline (imputer + forest) is saved with joblib as smart_room_occupancy_model.pkl and loaded by this page's FastAPI backend, so the live prediction uses the identical preprocessing.

Reproducibility note: the exported model was re-trained and verified with scikit-learn 1.7.2 — the version that reproduces the notebook's recorded results to the last decimal (99.41% / 98.88% / 98.72% / 98.80%).
